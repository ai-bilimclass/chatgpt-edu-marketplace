## 1. Pass the mandatory interview gate

Read `references/intake-gate.md` completely. Extract all known data and classify it as required lesson data, teacher profile, class context, reflection, preferences, constraints, and requested materials. Before asking for the curriculum section, inspect an annual KTP uploaded in the current Project and use its exact section title when the lesson match is unambiguous.

Do not ask again for information already present.

Before every new KSP, show a compact summary of the eleven mandatory fields, ask for all missing values, and request explicit confirmation of the complete data set. Stop and wait. Do not design lesson content or create a DOCX before confirmation.

For a subsequent lesson, reuse only unchanged values that the teacher confirms for the current lesson; obtain the new topic, objectives, requested lesson count, and any changed class context. Never ask about lesson duration: every lesson is fixed at 40 minutes. Store confirmed teacher and class data in the pedagogical-memory record for the current conversation.

In demonstration mode, show placeholders and conduct the real interview. Never supply answers for the teacher or use a technical script fixture as conversation evidence.

## 2. Confirm continuity and require reflection when applicable

If the conversation contains prior planning, determine whether this is the next lesson for the same class. Ask one short continuity question only when needed:

> Продолжаем планирование для этого же класса или это другой класс?

If it is the next lesson for the same class, check whether post-lesson reflection evidence is already available in the conversation. If not, pause lesson design and ask the three reflection questions from `pedagogical-memory.md` in Kazakh, Russian, or English according to the teacher's language or the current KSP language. Preserve the three core meanings, but adapt wording and examples to the subject, age, class profile, and known lesson context. Wait for the teacher's answers before continuing, unless the teacher explicitly asks to skip reflection or says no previous-lesson data exists.

## 3. Ask adaptive questions

After the mandatory gate has passed, ask only additional questions whose answers are missing. Prefer one compact grouped message. Questions must influence a concrete design decision.

For a first lesson, ask 0-5 diagnostic questions. For a subsequent lesson, do not substitute generic diagnostic questions for reflection on the previous lesson. Stop asking when there is enough information to design responsibly.

## 4. Analyze learning objectives

Read `references/learning-objectives.md` completely and apply its source, derivation, alignment, and validation rules.

For each teacher-provided objective:
- identify the required knowledge and skill;
- identify the observable learner product or performance;
- estimate cognitive demand;
- determine appropriate evidence of attainment;
- identify likely barriers and prerequisite knowledge.

Do not alter official wording.

## 5. Select the lesson model

Choose one primary model, such as:
- structured explicit instruction with guided practice;
- inquiry-based lesson;
- 5E lesson;
- problem-based lesson;
- project-oriented lesson;
- source-analysis lesson;
- laboratory or practical lesson;
- seminar/debate lesson;
- mixed model.

Give a 2-4 sentence justification in chat. Avoid listing pedagogical labels that are not operationalized in tasks.

## 6. Design backward from evidence

Define:
- lesson objective(s) derived from the official learning objective(s);
- 2-4 assessment criteria;
- evidence expected from learners;
- formative checks at key points;
- likely teacher responses to misunderstanding.

## 7. Build the lesson sequence

Create a realistic sequence totaling exactly 40 minutes for each requested lesson. When several lessons are requested, design and audit each lesson separately. Include:
- opening and activation;
- instruction or exploration;
- guided and/or independent practice;
- formative assessment and feedback;
- consolidation/reflection;
- use the localized final-stage name `Рефлексия` (Kazakh), `Рефлексия` (Russian), or `Reflection` (English); use reflection and actionable feedback rather than a former label for the final stage;
- homework where appropriate.

Every row in the lesson table must include concrete teacher actions, learner actions, resources, and assessment.

## 8. Differentiate

Provide:
- universal supports available to all;
- targeted scaffolds for identified needs;
- extension that deepens thinking rather than increases quantity;
- alternative ways to demonstrate learning where appropriate.

## 9. Add methodological appendix

Follow `references/output-structure.md`.

## 10. Audit and revise

Run the quality audit. Repair the plan before creating the final DOCX.
