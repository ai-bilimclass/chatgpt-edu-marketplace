# Стартовый каталог практических приёмов

**Статус: методическая рекомендация.** Каталог помогает реализовать уже выбранное методическое решение в конкретном учебном эпизоде. Приём не заменяет точную цель обучения, предметное содержание, основной метод урока или профессиональное решение учителя.

## Выбор по мыслительной функции

Сначала определить требуемое мыслительное действие ученика. Выбирать один основной приём для эпизода; второй добавлять только тогда, когда он выполняет отдельную необходимую функцию.

| Код функции | Мыслительный процесс | Предпочтительные приёмы |
|---|---|---|
| `understand_and_model` | понять новый способ и увидеть образец | `model-guided-independent`, `think-aloud`, `explain-own-words` |
| `retrieve_and_check` | извлечь знания и быстро проверить понимание | `retrieval-no-prompt`, `exit-ticket` |
| `compare_and_classify` | сравнить, выделить признаки, классифицировать | `comparison-table`, условно `venn-diagram` |
| `argue_and_evaluate` | сформулировать позицию, привести доказательство, оценить | `claim-evidence-reasoning`, условно `pops` |
| `read_and_transform` | понять источник и преобразовать информацию | `explain-own-words`, условно `jigsaw` |
| `apply_and_solve` | применить знание и решить предметную задачу | `real-life-task`, `example-counterexample` |
| `investigate_and_create` | выдвинуть предположение, проверить, создать решение | `predict-test-explain`, условно `scamper`, условно `case-method` |
| `analyze_and_improve` | найти ошибку, проверить качество и улучшить результат | `find-explain-error`, `criteria-check-revise` |

## 12 универсальных приёмов

### `model-guided-independent` — Показываю — делаем вместе — выполняешь сам

- Функция: освоение нового способа действия.
- Уместен: когда действие можно показать, выполнить с поддержкой и передать ученику.
- Ход: учитель моделирует с пояснением → класс выполняет аналогичный шаг с подсказками → каждый ученик выполняет новый пример самостоятельно.
- Индивидуальное доказательство: самостоятельный продукт последнего шага и краткое объяснение выбора.
- Ограничение: не считать совместное выполнение доказательством самостоятельного освоения.

### `think-aloud` — Рассуждение вслух

- Функция: сделать видимыми выбор стратегии, самопроверку и исправление.
- Ход: назвать задачу → проговорить решение и основания → показать проверку → предложить ученику воспроизвести ход на новом примере.
- Индивидуальное доказательство: объяснение учеником минимум одного решения и одной проверки.
- Ограничение: не превращать в длинную лекцию и не подменять речью ученика предметное действие.

### `retrieval-no-prompt` — Вспомни без подсказки

- Функция: извлечение ранее изученного из памяти.
- Ход: короткий вопрос без учебника и подсказок → индивидуальная фиксация ответа → сверка и коррекция.
- Индивидуальное доказательство: первоначальный ответ до обсуждения.
- Ограничение: использовать только для ранее изученного; не оценивать как незнакомое новое содержание.

### `explain-own-words` — Объясни своими словами

- Функция: выявить смысловое понимание.
- Ход: дать понятие, правило или результат → попросить объяснить простыми словами и привести предметный пример → уточнить неточность.
- Индивидуальное доказательство: объяснение и пример, которые сохраняют существенные признаки.
- Ограничение: упрощение языка не должно искажать содержание.

### `comparison-table` — Сравнительная таблица

- Функция: сравнение и систематизация по нескольким критериям.
- Ход: определить объекты и критерии → заполнить признаки → сформулировать сходства, различия и вывод.
- Индивидуальное доказательство: заполненная строка или таблица и вывод по критериям.
- Ограничение: критерии должны быть содержательными, а не декоративными.

### `claim-evidence-reasoning` — Утверждение — доказательство — объяснение

- Функция: аргументация.
- Ход: сформулировать утверждение → привести данные, факт, фрагмент или результат → объяснить, почему доказательство поддерживает утверждение.
- Индивидуальное доказательство: все три связанные части.
- Ограничение: мнение без доказательства и цитата без объяснения не считаются завершённым ответом.

### `example-counterexample` — Пример и контрпример

- Функция: проверить границы понятия, правила или классификации.
- Ход: назвать существенные признаки → привести подходящий пример → привести контрпример → объяснить границу.
- Индивидуальное доказательство: корректная пара с объяснением.
- Ограничение: контрпример должен нарушать существенное условие, а не быть случайно непохожим.

### `predict-test-explain` — Предскажи — проверь — объясни

- Функция: исследовать связь причин, условий и результата.
- Ход: индивидуальный прогноз с основанием → безопасная проверка или анализ данных → сопоставление → объяснение расхождения.
- Индивидуальное доказательство: исходный прогноз и итоговое объяснение.
- Ограничение: соблюдать предметную и лабораторную безопасность; не выдавать имитацию проверки за наблюдение.

### `real-life-task` — Задача из жизни

- Функция: перенос знания в реалистичный контекст.
- Ход: задать правдоподобную ситуацию и данные → выполнить предметное действие → обосновать решение и его ограничения.
- Индивидуальное доказательство: решение с предметным основанием.
- Ограничение: бытовой сюжет должен требовать целевое действие, а не маскировать обычный пример.

### `find-explain-error` — Найди и объясни ошибку

- Функция: диагностика ошибочного рассуждения.
- Ход: предъявить правдоподобное решение → локализовать ошибку → объяснить причину → исправить и проверить.
- Индивидуальное доказательство: место ошибки, объяснение и исправленный результат.
- Ограничение: ошибка должна быть содержательной и соответствовать возрасту.

### `criteria-check-revise` — Проверь по критериям и исправь

- Функция: улучшение работы по прозрачным критериям.
- Ход: применить 2–4 наблюдаемых критерия → отметить доказательства → внести конкретное исправление → повторно проверить.
- Индивидуальное доказательство: версия до и после с объяснением изменения.
- Ограничение: взаимопроверка не заменяет индивидуального подтверждения результата.

### `exit-ticket` — Выходной билет

- Функция: короткое итоговое доказательство достижения цели урока.
- Ход: один-два вопроса по ключевому действию → индивидуальный ответ без групповой помощи → решение учителя о следующем шаге.
- Индивидуальное доказательство: личный ответ каждого ученика.
- Ограничение: вопрос должен измерять цель, а не настроение или общую самооценку.

## 5 условных приёмов

Условный приём выбирать только при выполнении всех условий и фиксировать причину выбора в практическом эпизоде.

### `jigsaw` — Джигсо

- Использовать: материал можно разделить на равноценные части; ученики способны самостоятельно прочитать часть и обучить других; времени достаточно для экспертной и смешанной групп.
- Обязательно: опора для чтения, проверка понимания эксперта и индивидуальное итоговое задание.
- Не использовать: при критически новом сложном содержании без предварительного обучения или когда отсутствие одного участника разрушает результат группы.

### `scamper` — SCAMPER

- Использовать: требуется проектирование, преобразование объекта или генерация вариантов по уже понятным критериям.
- Обязательно: выбрать только релевантные операции, затем оценить варианты по критериям и доработать один.
- Не использовать: для первичного объяснения факта, отработки точного алгоритма или свободной генерации без предметных ограничений.

### `pops` — ПОПС-формула

- Использовать: учителю нужен краткий речевой каркас позиции «я считаю — потому что — могу доказать — делаю вывод».
- Обязательно: доказательство должно быть проверяемым и связано с выводом.
- Не использовать: как отдельный новый метод, если функцию уже полностью реализует `claim-evidence-reasoning`; в этом случае ПОПС является только языковой опорой.

### `venn-diagram` — Диаграмма Венна

- Использовать: сравниваются два-три объекта по небольшому числу признаков и важна визуализация пересечения.
- Обязательно: после диаграммы сформулировать содержательный вывод.
- Не использовать: при многих критериях, сложных отношениях или необходимости точной систематизации; выбрать `comparison-table`.

### `case-method` — Кейс-метод

- Использовать: подготовлена достоверная ситуация с достаточными данными, несколькими обоснованными решениями и ясными критериями оценки.
- Обязательно: отделить факты от предположений, назвать ограничения данных и получить индивидуальное решение до общего обсуждения.
- Не использовать: если кейс сводится к угадыванию, не содержит нужных данных или требует непроверенных фактов.

## Общие ограничения

- Не показывать учителю весь каталог без запроса; выводить только фактически применённый приём и его функцию.
- Не выбирать приём по привлекательности названия. Основание выбора: точная цель, этап, требуемый мыслительный процесс, содержание, возраст, время и доступность.
- Для групповой работы всегда предусматривать индивидуальное доказательство каждого ученика.
- Не приписывать приёму доказанную эффективность для конкретного урока до получения результатов учеников.
- Встроенный каталог использовать первым. Если ни один приём не закрывает учебную функцию либо учитель прямо просит альтернативу, применить [политику гибридного поиска](practical-technique-search-policy.md); найденный приём не добавлять в каталог автоматически.
