# Контракт входных данных

## Повторно использовать контекст

До любых вопросов проверить текущий диалог, приложения и структурированную передачу данных.

- Если есть готовый ҚМЖ/КСП или `worksheet_handoff`, извлечь предмет, класс, язык, тему и учебную цель и не спрашивать их повторно.
- Если один из этих параметров уже однозначно указан пользователем в текущем диалоге, также не переспрашивать его.
- Более новое прямое указание пользователя имеет приоритет над ранее извлеченным значением.
- После извлечения спрашивать только отсутствующие обязательные параметры. В типичном продолжении после ҚМЖ/КСП это вид оценивания, уровни Блума и количество заданий.
- Не показывать пользователю служебные имена полей и внутреннюю карточку, если он не запросил технический формат.
- Если класс отсутствует, одной строкой попросить указать точный класс от 1 до 11.

## Обязательные поля

| Поле | Допустимые значения | Правило |
|---|---|---|
| `grade` | целое 1–11 | Не смешивать требования разных ступеней |
| `assessment_type` | `PRACTICE`, `FO`, `INTERIM`, `SOR`, `SOCh` | Для 1 класса использовать внутреннее значение `PRACTICE`; `INTERIM` — только для 2–4 классов |
| `subject` | название предмета | Использовать официальное название пользователя |
| `language` | `ru`, `kk` или `en` | Весь ответ и все пояснения писать только на этом языке |
| `content_scope` | тема/раздел; для СОЧ — четверть и разделы | Не оценивать неизученное содержание |
| `learning_objectives` | список кодов и полных формулировок | Не восстанавливать код по памяти |
| `bloom_levels` | один или несколько уровней | Уточнить количество/долю заданий по уровню, если это существенно |
| `task_count` | положительное целое | Отличать задание от подпункта; для `SOCh` брать из спецификации или подтверждённого проектного решения учителя |

## Условно обязательные поля

| Поле | Когда нужно |
|---|---|
| `quarter` | Четвертное планирование ФО, промежуточное оценивание, СОЧ или привязанный к четверти СОР |
| `track` | 10–11 класс, если различаются ЕМН/ОГН |
| `time_minutes` | Промежуточное оценивание, СОР/СОЧ; для ФО при ограничении урока |
| `max_score` | Промежуточное оценивание, СОР/СОЧ; для ФО не использовать как сумму заданий |
| `formative_scale_max` | Для ФО 2–4 классов должно быть равно 10; для 5–11 классов не использовать |
| `planning_scope` | `single` или `quarter` для ФО 2–4 классов |
| `quarter_learning_objectives` | При проверке или создании четвертного плана ФО 2–4 классов |
| `technical_specification` | СОЧ; при наличии — главный источник структуры |
| `specification_task_count` | СОЧ, если количество явно установлено спецификацией; должно совпадать с `task_count` |
| `soch_descriptors_required` | Только если утверждённая спецификация прямо требует дескрипторы; иначе не использовать |
| `task_formats` | если учитель ограничивает закрытый выбор, открытый ответ, соответствие, последовательность, практику или устную/письменную работу |
| `allowed_resources` | калькулятор, карта, формулы, словарь, оборудование и т. п. |
| `learner_supports` | только конкретные необходимые адаптации |
| `teacher_experience_level` | `trainee`, `beginner`, `experienced` или `methodologist`; по умолчанию `trainee` |
| `weekly_hours` | Обязательно до разработки СОЧ в 5–11 классах; положительное число |
| `annual_hours` | Положительное число, если указано в КТП или учебном плане; не заменяет `weekly_hours` |
| `grade_reporting_period` | `quarter` или `semester`; при `weekly_hours: 1` в 5–11 классах — `semester` |
| `semester` | `1` или `2`, если создаётся полугодовой план оценивания |
| `sor_count_in_quarter` | Целое число от 0 до 2 |

## Нормализация запроса

Сформировать перед разработкой краткую карточку:

```yaml
assessment_type: SOR
grade: 7
subject: Биология
language: ru
content_scope: Питание живых организмов
learning_objectives:
  - "7.x.x.x — полная формулировка пользователя"
bloom_plan:
  apply: 2
  analyze: 1
task_formats:
  - multiple_choice
  - short_answer
  - matching
task_count: 3
time_minutes: 20
max_score: 12
status: official | draft
teacher_experience_level: trainee
weekly_hours: 2
grade_reporting_period: quarter
```

Если сумма количества заданий в `bloom_plan` не равна `task_count`, уточнить приоритет или предложить исправленную раскладку.
Для `SOCh` при наличии `specification_task_count` требовать точного совпадения. Без спецификации разрешать только проект после явного подтверждения количества учителем.

Для любого `SOCh` в 5–11 классах сначала проверить предметные исключения, затем получить `weekly_hours`. При `weekly_hours: 1` не формировать СОЧ и не спрашивать его время, максимальный балл или структуру. Выдать нормативное пояснение, использовать `grade_reporting_period: semester` и предложить СОР либо план оценивания на полугодие. Не создавать «СОЧ за полугодие».

## Короткая форма запроса для пользователя

`Класс: …; вид: …; предмет: …; язык: …; тема/раздел/четверть: …; цели обучения: …; Блум: …; заданий: …; время: …; для промежуточного оценивания, СОР/СОЧ — балл и спецификация: …`
